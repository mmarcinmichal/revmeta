agent configuration

Relates specified review workflow stages to the human, automated, or integrated human-machine configuration that performs substantive work at those stages.

Facet boundary: The primary boundary is AutomatedAgent versus HybridHumanMachine, plus coexistence of SingleHumanReviewer and MultipleHumanReviewers within a stage when procedures differ by substage.

Automated agent

revmeta:hasAgentConfiguration.AutomatedAgent · Annotation depth: OPTIONAL_DETAIL

A stage-qualified configuration in which software or an algorithm executes a substantive review task without concurrent substantive human judgment in that execution step, although humans may configure, supervise, or review outputs before/afterward.

CODE WHEN

  1. A substantive review task at a specified workflow stage is executed by software/algorithmic automation without concurrent substantive human judgment in that execution step.

DO NOT CODE WHEN

  1. Do not code passive database/search/reference-management software.
  2. Do not use when human and machine make integrated substantive decisions within the same task; use HybridHumanMachine.

Boundary notes

  1. Passive software/tool use is insufficient.
  2. Distinguish from HybridHumanMachine by whether substantive human judgment is concurrent/interdependent within the same task.

Positive examples

  1. The methods explicitly state that a automated agent configuration performed a specified workflow stage, and the stage is recorded.

Negative examples

  1. The publication has evidence of automated agent only by inference from authorship or generic software use, not an explicit stage-qualified workflow description.

analytical object type

Relates the review to broad categories that themselves function as material analytical dimensions or direct targets of cross-corpus comparison, classification, mapping, appraisal, aggregation, interpretation, or synthesis. Mere evidence-carrier status, routine extraction, evaluation context, or named-instance occurrence is insufficient.

Facet boundary: Multi-label coexistence is allowed only when each neighbor has independent material evidence. Do not co-code broader/adjacent terms merely because one concrete object can be described in several everyday-language ways.

Argumentative contribution

revmeta:claimsContributionType.ArgumentativeContribution · Annotation depth: OPTIONAL_DETAIL

A principal explicitly claimed contribution that advances a structured thesis, critique, position, or reasoned argument derived from the review synthesis rather than merely reporting evidence.

CODE WHEN

  1. Gate 1 — principal claim: central text explicitly presents a structured thesis, critique, position, or argument as a principal contribution/value added by the publication.
  2. Gate 2 — type fit: the claimed contribution advances and supports a reasoned position/critique derived from the synthesis rather than merely interpreting results.
  3. Gate 3 — realization: the claimed contribution is materially developed in the publication rather than merely promised, mentioned, or implied by an artifact.

DO NOT CODE WHEN

  1. Do not infer a contribution claim solely from the existence of a corresponding artifact, method, section, or recommendation.
  2. Generic usefulness, ordinary synthesis, incidental outputs, and routine implications are insufficient.
  3. If the authors make no principal contribution claim of this type, code 0 even when related content is present.

Boundary notes

  1. Ordinary interpretation or critique is insufficient unless a structured argument/position is claimed as principal contribution.
  2. May overlap with PositionFunction but requires an independent contribution claim.

Positive examples

  1. The abstract or contribution statement explicitly presents a argumentative contribution as a principal contribution and the paper materially realizes it.

Negative examples

  1. A related element appears in the paper, but it is not explicitly claimed as a principal argumentative contribution.
